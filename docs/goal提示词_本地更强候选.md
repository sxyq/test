# Goal 提示词（本地更强候选）

你不是从 `submission` 现有版本里挑一个“最好”的版本，也不是沿用已有技术路线做微调对比。

你的目标是：

1. 把当前本地所有版本当作**证据库**，而不是候选空间上限
2. 基于已有技术演进、提交记录、逐页优化策略文档，以及本地环境约束，重新组合出一个**本地证据上更强的新候选**
3. 优先做**轻量但尽量全面**的本地验证，验证维度至少包括：
   - 真实权重可加载性
   - 真实格式小样本前向链路
   - 结构代理 latency
   - 小规模 holdout AUC / PCOC / 校准趋势
   - 打包可提交性
4. 不把 Apple 本机验证等同于 AI Studio 最终结论，但要尽可能把本机能做的验证做满
5. 允许下载在线公开数据集，并构造本地 holdout / 样本切片来支持验证

执行原则：

- 不以 `V175~V180` 或任意已有版本为终点
- 旧版本只用于拆解哪些改动有效、哪些改动互相冲突
- 优先寻找**结构更优 + 本地验证更稳 + 后续可提交**的新组合
- 每轮结论都要落到本地文档和结果文件，不只停留在聊天总结

当前建议主问题可写成：

> 请查看我本地 `submission`、`docs/提交记录_分数_方法_论文索引.md`、`docs/TensorRT讲座推理性能优化策略整理.md`、本地验证脚本与结果文件。不要从已有版本里直接选一个最优解，而是把它们当作证据库，结合我本机 Apple Silicon 环境与可下载的在线数据，设计并验证一个本地证据上全面强于已有版本的新候选。请优先使用轻量化验证，但覆盖真实权重、真实格式样本、holdout 质量代理、结构代理性能和可提交性检查，并把过程与结论落盘。
