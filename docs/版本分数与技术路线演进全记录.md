## 3. 当前版本结论

截至当前记录，主线判断如下：

| 角色 | 版本 | 结论 |
|---|---|---|
| 当前总主线 | `V207-EMB-INT8-ONLY-sxyq` | 当前线上最佳，`74.03155 / 21.45791s` |
| 原始未量化参考底座 | `V201-TRT-MOE-UNQUANT-sxyq` | plugin/kernel 原生高分基线 |
| PTQ-prep 对齐底座 | `V205-SELECTIVE-PTQ-PREP-sxyq` | 文档边界最干净的量化准备版 |
| TRT 重构参考线 | `V194-TRT-MOE-STACKED-sxyq` | 本地重构后的 TRT 主线参考 |
| 结构压缩参考线 | `V185-V177-STACKED-SUBMIT-sxyq` | 纯 PyTorch / 结构压缩路线参考 |

当前最重要的技术结论也已经稳定：

1. `V201` 证明原生 `plugin/kernel` 主链路是高价值底座；
2. `V205` 证明 PTQ-prep 边界可以收得很干净，但默认 scoring path 仍基本贴着 `V201`；
3. `V206` 证明“激进全量 INT8 叠加”没有兑现端到端收益；
4. `V207` 证明当前真正有效的量化相关变量是 `RepEncoder embedding INT8` 单变量；
5. `V208` 证明“尽可能多叠加”会破坏当前主链路收益。

## 4. 技术路线分期演进

### 4.1 第一阶段：早期 embedding / 输出 / 壳层治理

这一阶段的核心目标不是改模型结构，而是先把端到端推理壳层整理出来。

代表版本：

| 版本 | 关键变化 | 当前结论 |
|---|---|---|

| `V24-SPARSE-EMB-sxyq` | `embedding_bag` 合并思路 | 保留为 embedding 融合方向的经验样本 |
| `V30-CPU-METADATA-sxyq` | CPU metadata 壳层 | 后续被并入 TRT 壳层经验 |
| `V32-CHUNKED-COLLECT-sxyq` | chunked collector | 后续被 TRT 版本复用 |

4. compile 只有在 warmup / scope / shape 处理正确时才有意义。

## 6. 当前已被证伪的路线

以下路线不应再作为默认主线推进：

| 路线 | 代表版本 | 结论 |
|---|---|---|
| eager 全量 INT8 | `V105`、`V147`、`V165`、`V206` | 反量化与桥接开销过大，端到端不成立 |
| sparse eager MoE | `V135`、`V146`、`V150`、`V151`、`V152`、`V159`、`V160`、`V163`、`V164` | dispatch/sort/scatter/gather 成本打不过 dense 规整化 |
| 跳层 skip | `V120-V129`、`V131` | 即使高分，也不合规 |
| 无 shape 治理 compile / graph | `V142`、`V149`、`V166` | 动态 shape / 初始化成本会直接吞掉收益 |
| 整包吞吐默认项一次性叠加 | `V202`、`V208` | 会破坏当前 `plugin/kernel` 主链路收益 |

## 7. 当前仍值得继续的路线

结合现有实测，后续真正值得继续的只有三条：

1. `V207` 主线继续做小范围单变量叠加
   - 只允许低冲突增量；
   - 任何新变量都必须先相对 `V207` 做对照。

2. `V205` 继续承担 PTQ-prep / selective PTQ 分支
   - 继续保持 `MoE plugin` 与 `gate/routing` 为浮点；
   - 只尝试非 `MoE` dense 子图。

3. `V194/V201` 继续承担 TRT / runtime 结构对照
   - 用于验证 plugin/native kernel 之外的壳层项是否真的有独立正收益。
